# Threat model: Fiber contrib

## Start here

Fiber contrib is 24 independent Go modules (the `v3` line) that add middleware and one service helper to Fiber. Most are small, and several sit on the trust boundary: token and ticket verification (`jwt`, `paseto`, `spnego`), authorization (`casbin`, `opa`), a WAF (`coraza`), and two protocol servers (`websocket`, `socketio`). They have just been through a concentrated review-and-fix cycle. Since 1 July 2026 `main` has 807 non-merge commits; 434 are dependabot's. Of the other 373, 219 mention a fix, bug, panic, race, leak, bypass, redaction, bound or the like, and they cluster in `spnego` (75 commits, with review passes numbered up to the twentieth), `prometheus` (65), `uptime` (50), `websocket` (28), `jwt` (23), `otel` (22), `monitor` (20), `socketio` (14) and `circuitbreaker` (11). Much of that review was automated (commit messages cite review agents, CodeRabbit, Copilot and Codex), so the shallow findings are gone. Spend your time where a bug is still likely, in this order:

1. **Siblings of recent fixes, in the modules that were not part of the cycle.** `hcaptcha`, `opa`, `casbin`, `paseto`, `swaggo`, `swaggerui`, `fgprof`, `zap`, `loadshed`, `i18n`, `sentry` and `coraza` have two commits or fewer since July. For each class in "Bug classes seen here", state the invariant the fix restored, then look for a module that does not enforce it. The full history is in `/src/.git` (5,278 commits and 598 tags; the v3 modules are tagged `v3/<module>/vX.Y.Z`). This has the best yield per hour.
2. **Gates and ordering in `socketio` and `websocket`.** Three fixes on branches the maintainers named `...-vulnerability` were gate-ordering bugs in `socketio` polling (#1909, #2175, #2201). Every other way into the same code, whether a transport, a framing, a batch, a retry or a race, deserves the same question: can anything run before the handshake and the application's auth have finished, or after they refused?
3. **Code rewritten for speed or parsed by hand.** `websocket/coalesce.go` (a hijacked-connection wrapper that coalesces writes), `websocket/read.go`, `socketio/codec.go` and `socketio/polling.go`, `jwt/challenge.go` (response challenge composition) and `jwt/crit.go` (`crit` header validation), the keytab cache and response recorder in `spnego`, `uptime/internal/storage/redis.go` (831 lines), the series cache in `prometheus`, the collectors in `monitor`. Read them line by line, with the tests that pin their behavior beside them.
4. **Differentials.** A request has to mean the same thing to the router, to the module's guard and to whatever receives it: `c.Path()` against a policy or a `Next` predicate, a header read once against the same header read as a list, the request Coraza inspects against the one the handler gets.
5. **Fail-open paths and lifetimes**: every callback or dependency inside a security decision, and every object (`Conn`, session, circuit, collector, storage handle) that outlives the request that made it, with `-race`.

If you can run workers in parallel, give each one area and have it read its files completely: (a) `jwt`, `paseto`, `spnego`, `casbin`, `opa`, `hcaptcha`, `coraza`; (b) `websocket` and `socketio`; (c) `prometheus`, `otel`, `monitor`, `uptime`, `fgprof`, `loadshed`, `circuitbreaker`; (d) `sentry`, `newrelic`, `zap`, `zerolog`, `i18n`, `swaggerui`, `swaggo`.

Working rules. Give a hypothesis about fifteen minutes; without a lead, move on. Once a root cause has a reproducer and a patch, stop and write it up rather than listing variants. Read the tests for what they pin, not in full (`socketio`'s are 236 KB, `jwt/rfc_test.go` 1,100 lines): a test that asserts a behavior marks it as deliberate. Skip `example/` directories, `testdata/`, Grafana dashboard JSON, `.github/` and the README pages of modules you are not on.

## What this project does and where untrusted input enters

Each module is a library: an application imports `github.com/gofiber/contrib/v3/<name>` (`casbin` is `.../v3/casbin/v2`), registers it on a Fiber v3 app and calls `app.Listen`. You are auditing code that runs inside that application, not an application. There are about 21,700 lines of non-test Go in total (tests: 42,000), no cgo and no generated code. There is no `go.work` and no `replace` directive: every module builds against the published Fiber `v3.6.1`, `gofiber/utils/v2` `v2.6.2` and fasthttp `v1.76.0` that its `go.mod` pins, not against the Fiber checkout. The one cross-module dependency is `socketio` on the published `websocket` `v1.2.9`. The `v2` line lives on another branch and is not scanned.

- **Authentication and authorization.** `jwt` (golang-jwt v5, `MicahParks/keyfunc`): the token comes from an extractor (the `Authorization` header by default; query, form field, route parameter, cookie or header on request), and `JWKSetURLs` makes the module fetch keys over HTTP(S). `paseto` (`o1egl/paseto` v2, local or public tokens): the token comes from an extractor. `spnego` (gokrb5 v8): `Authorization: Negotiate <AP-REQ>`, a keytab from the application's `KeytabLookup`, and optionally a session cookie through the application's `SessionManager`. `casbin` decides for a subject the application's `Lookup` supplies, from `c.Path()` and the method (`RoutePermission`) or from fixed permission and role names. `opa` evaluates a Rego policy over `c.Path()`, the method and, on request, chosen headers and the query string. `hcaptcha`: a token from the JSON body, verified against a siteverify URL. `coraza` (Coraza v3 WAF): the whole request, rebuilt as an `http.Request` through `adaptor.ConvertRequest`.
- **Availability controls.** `loadshed` (CPU sampler) and `circuitbreaker` (a state machine fed by response statuses).
- **Protocols.** `websocket` (fasthttp/websocket, plus the `websocket/event` helper): handshake headers, `Origin`, frames. `socketio` (Engine.IO v4 and Socket.IO v5): WebSocket frames, and opt-in HTTP long-polling (`EnablePolling`) with POST bodies that may be batched, base64 or compressed.
- **Pages and endpoints that serve data by design**: `monitor` (runtime and system metrics, HTML dashboard), `uptime` (status page, JSON API, endpoint probes, a Redis store), `prometheus` (instruments requests and serves metrics), `fgprof` (`/debug/fgprof`), `swaggerui` and `swaggo` (Swagger UI and the spec).
- **Observability and logging**: `otel`, `sentry`, `newrelic`, `zap`, `zerolog`. They read request headers, URL, body and peer, and write them to logs, traces, metrics or a vendor.
- **Other**: `i18n` (language from the `lang` query parameter or `Accept-Language`) and `testcontainers` (starts Docker containers for development and tests).

Treat all of the following as attacker-controlled: the request target (path, query, spellings the router accepts), every request header (`Authorization`, `Cookie`, `Origin`, `Accept-Language`, `X-Forwarded-*`, `Upgrade`, `Sec-WebSocket-*`, `Content-Encoding`), request bodies (JSON, form, polling POST bodies), WebSocket frames and Socket.IO packets (text and binary, `0x1E`-batched), JWTs and PASETO tokens including their headers, Kerberos tickets, and the session cookie a `spnego` `SessionManager` reads. The far end of an outbound call is chosen by the application but its answer is not trusted code: a JWKS document decides which keys verify tokens, and an hCaptcha, OTLP, Sentry, New Relic or probe target can answer anything.

Trusted: application code and handlers, every `Config` and the callbacks in it (`Next`, `Lookup`, `KeyFunc`, `ValidateFunc`, `TokenProcessorFunc`, `IsFailure`, `OnShed`, `RedactHeader`, `LangHandler`), keys, keytabs, policies, Casbin models and message files, the Redis server, templates, the operator who mounts a page, and whatever sits in front as a reverse proxy that `TrustProxyConfig` lists.

The defaults decide severity, so know them. Fiber does **not** recover panics, so one that escapes a handler ends the process unless the application mounts `recover`; `BodyLimit` is 4 MiB and `TrustProxy` is off. In `websocket.New`, an empty `Origins` allows every origin, and there is no read limit unless the handler calls `SetReadLimit`; `websocket/event` defaults to 1 MiB inbound, 25 s pings and a 10 s write timeout; `EnableCompression` is off. In `socketio`, polling is off, `MaxPayload` is 1 MB, the handshake has 10 s, `WriteTimeout` is 0, and the per-connection send queue is 100. `jwt` pins the algorithm only when `SigningKey.JWTAlg` (or every entry of `SigningKeys`) names one; a missing token is a 400 and a bad one a 401. `casbin`'s default `Lookup` returns an empty subject, which is always a 401. `opa` and `casbin` answer 500 on an evaluation error and deny whatever the policy does not allow. `coraza` loads no rules until `DirectivesFile` is set. `hcaptcha` calls `fasthttp.Do`, which sets no read or write deadline. `uptime` has no in-memory store: it needs the Redis `Store` or a custom `Storage`. Pages that serve data (`monitor`, `uptime`, `prometheus`, `fgprof`, `swaggerui`, `swaggo`) serve it to anyone who can reach them unless the application puts authentication in front.

## What the modules promise (a violation is a finding)

Each promise ends with the check that tests it.

1. **A verifier decides from its configuration, not from the token.** `jwt` pins the algorithm when configured, refuses `alg: none`, never reads a key out of `jwk`, `jku`, `x5u` or `x5c`, rejects a `crit` header it was not told to understand, refuses `b64`, validates `exp` and `nbf`, and requires unpadded base64url (see "What the middleware enforces" in its README). `paseto` accepts only what its key verifies, with `exp`, `sub` and `aud` checked by the default validator. `spnego` authenticates only when gokrb5 reports success. *Check:* every `alg`, `kid`, `crit`, `typ` and key-type combination against a reference parser built on the same library with the same options; `jwt/rfc_test.go` is the existing oracle. The module may be stricter than the reference, never looser.
2. **A guard that fails, refuses.** `coraza` answers 500 on any WAF failure and recovers panics; `opa` and `casbin` answer 500 on error and deny whatever the policy does not allow; `spnego` answers a sanitized 500 when the keytab lookup or gokrb5 fails; `prometheus` reads a panicking `Next` as "skip", so a metrics endpoint gated by `Next` stays closed (#2184). `loadshed` is the documented exception. *Check:* inject an error, a panic, a nil result and a slow return into every callback and dependency of a decision, and see what a protected route answers.
3. **Nothing is processed before the handshake and the application's auth finished, or after they refused.** In `socketio` no packet other than a successful CONNECT reaches a listener first, for either transport and in any framing, and nothing behind a rejected or disconnecting packet in the same frame, batch or POST runs. Overlapping POSTs queue before they allocate. In `websocket`, `Origins` and the handshake checks run before the handler. *Check:* the gate matrix under "Hypotheses".
4. **Sensitive values stay out of responses, logs and telemetry that the docs do not name.** `websocket` sends the peer a fixed `internal error`, never a panic value. `spnego` answers failures with a fixed `Internal Server Error`, drops gokrb5's keytab parse errors (which embed the key), and quotes and caps what it does log; what a custom `KeytabLookup` returns is the application's to keep clean. `uptime` redacts storage errors from its status payload. `zerolog` redacts `Authorization`, `Cookie`, `Set-Cookie` and similar headers by default, `newrelic` forwards an allowlist of headers, `otel` redacts credential-bearing query parameters. *Check:* grep each module for an error, a panic value or a request header reaching a response, a log call, a metric label or a span attribute.
5. **Inbound sizes, counts and labels are bounded before the allocation.** `websocket/event` caps frames at 1 MiB; `socketio` has `MaxPayload`, `MaxAuthPayload`, `MaxBatchPackets`, `MaxEventNameLength`, `MaxEventArgs` and `PollingMaxBufferSize`; `prometheus` takes the `path` label from the route pattern (a request that matches no route is not recorded, or gets one fixed label) and bounds the method label; `uptime` bounds its key growth. *Check:* memory and time per request at the limit, then at double, including bodies that arrive compressed.
6. **Request-owned memory is copied before it outlives the request.** Strings and slices from the Fiber context alias fasthttp's buffers. `sentry`, `websocket`, `spnego`, `socketio` polling and `prometheus` copy before they store; `opa` hands views to `Eval` and must not see them retained. *Check:* reuse one `fasthttp.RequestCtx` for many requests with a sink that records what it is given, under `-race`.

The README of each module is the maintainers' statement of intended behavior. When it says a behavior is intended or something the application must do, that is not a finding. When the code contradicts it, that is.

## Components that matter most / least

Most important, in this order. The count after each is its non-merge, non-dependabot commits since 1 July (a rough measure of how new the code is).

1. **`socketio`** (3,986 lines, 14) and **`websocket`** (2,202, 28, including `event/event.go`, 1,214 lines). Two protocol parsers, a process-wide pool of connections keyed by UUID, timers and teardown paths. A mistake here runs application code for a client that should not have reached it.
2. **Verifiers and policy glue**: `jwt` (1,166, 23), `spnego` (1,380, 75), `paseto` (298, 2), `casbin` (303, 2), `opa` (106, 2), `hcaptcha` (143, 1), `coraza` (1,083, 2).
3. **Pages and stores that serve what a request names**: `uptime` (2,808, 50; routing in `uptime.go`, the Redis store in `internal/storage/redis.go`), `monitor` (1,188, 20), `swaggerui` (203, 2), `swaggo` (561, 2), `fgprof` (67, 1).
4. **Instrumentation that reads every request**: `prometheus` (1,716, 65), `otel` (1,465, 22), `sentry` (206, 2), `newrelic` (207, 5), `zerolog` (485, 4), `zap` (686, 2).
5. **State machines**: `circuitbreaker` (595, 11), `loadshed` (284, 2).

Less important, still in scope: `i18n` (341), `testcontainers` (271; development and test tooling, so only unsafe defaults, argument injection into Docker, or secrets it exposes count).

Out of scope: `_test.go` files, `example/` and `testdata/` directories, the Grafana dashboard JSON under `prometheus`, the READMEs, and `.github/`.

Dependencies. Fiber core, fasthttp and `gofiber/utils`, `gofiber/schema` and `gofiber/storage` are maintained elsewhere (Fiber core is enrolled as its own project). A flaw that lies wholly inside them, or inside another third-party module (golang-jwt, keyfunc, gokrb5, Casbin, OPA, Coraza, `o1egl/paseto`, fasthttp/websocket, go-redis, client_golang, OpenTelemetry, sentry-go, the New Relic agent, zap, zerolog, go-i18n, swag, go-openapi, gopsutil, testcontainers-go), belongs to its maintainers. Report it here only when a contrib module is what exposes it under its default or documented configuration, say which module holds the fix, and give the reproducer as a contrib application. Module sources are in the module cache (`cd /src/v3/jwt && go list -m -f '{{.Dir}}' github.com/golang-jwt/jwt/v5`).

## Bug classes seen here (hunt for variants)

Numbers like #2175 are pull requests and appear in merge commits (`git log --grep '#2175'`); short hashes are commits. For each class: the fixes, then the siblings worth checking.

1. **A gate does not cover everything behind it.** `socketio` polling: #1909 (`b93ed7cb`, `46611bb8`: a batch kept running after an auth rejection), #2175 (`a3bebe08`, `ff0c6c41`: packets before CONNECT, including base64 binary ones), #2201 (`31eb97d3`, `1fd03ba2`: the body was copied before the per-session gate). `websocket`: `9a85d694` (a partial handshake now reaches the upgrader), `d674014a` and `f9f109eb` (reads blocked across shutdown). Siblings: every dispatch site in `socketio.go` (`read`, `dispatchEIOFrame`, `dispatchEIOPacket`, `handleSIOPacket`, `connectPolling`, `ingestPolling`), a second CONNECT for another namespace, ACK and binary packets, a POST racing a GET drain, `Close`, `Shutdown` and `Drain` against in-flight packets.
2. **A security decision fails open on a panic or an error.** `6e25fc95` (#2184, `prometheus` `Next`), `2c0a7357` (`spnego`, a malformed token panicked every protected route), `29b18ad8` and `6d1093b9` (`jwt`: a panic with non-pointer custom claims, a typed-nil error), `fe311afc` and `a8603cfc` (`prometheus`, instrumentation must never take a request down). Siblings: every `Next`, `Lookup`, `KeyFunc`, `ValidateFunc`, `IsFailure`, `OnShed` and `Eval` call that is not wrapped; what a protected route answers when each panics, returns nil, or blocks (`opa` evaluates with `context.Background()`, `hcaptcha` has no deadline).
3. **A mutable package-level default.** #2185 (`59324dac`, `29843fa6`: `prometheus.New()` ignored an edited `ConfigDefault`, and shared its bucket slices). Siblings: every exported `ConfigDefault` and `DefaultConfig` (`circuitbreaker`, `loadshed`, `casbin`, `paseto`, `swaggerui`, `zap`, `zerolog`), slices and maps shared by copies, and handlers built at package init (`swaggo.HandlerDefault`).
4. **A sensitive value reaches a response, a log or a telemetry sink.** #2169 (`479a18d1`, `244b39d4`: `zerolog` redaction), `7b71f850` and `8ac95271` (`newrelic` header allowlist), `c6c218f6` (`otel` query redaction, trace headers), `1758b07d` (`uptime` storage errors in the status payload), `e0f8e8a0` and `8bd46cc3` (`spnego`), `76a6f18c` and `584430bb` (`websocket` panic values). Siblings: `zap` has a shorter header redaction list than `zerolog` (compare `sensitiveRequestHeaders` in `zap.go` with `redactSensitiveHeader` in `zerolog/config.go`) and logs the raw `X-Forwarded-For`; `opa`, `hcaptcha` and `paseto` write error text into responses; `sentry` and `otel` record bodies, URLs and `enduser.id`; `coraza` logs the path and client IP when it recovers a panic.
5. **Series, keys or sessions created from request data without a bound.** #2183 (`91749c11`, `8ee711be`: the in-flight gauge's method label), `366e4b5e`, `029043a5` and `449cd0c2` (the unmatched-route label), `4c563e08` and `1246334c` (invalid UTF-8 labels), `baa51656` and `3e4940f6` (`uptime` keys and refreshes). Siblings: `newrelic` names each transaction after the raw request path, `otel` attribute values, `DynamicLabels`, the `socketio` and `websocket/event` pools, polling sessions per client, anything keyed by a header or a query value.
6. **A body or frame is materialized before its limit applies.** `31eb97d3` (polling bodies, which are decompressed to `BodyLimit` rather than `PollingMaxBufferSize`), `85efb0d7`, `7f715936` and `a7653a80` (`otel` request size), `55cccece` and `befe2ce2` (`prometheus` sizes), `cb7807bf` (`event` frames), `5b195386` (`socketio` array elements), `b5390b85` (an overflowing size precomputation). Siblings: `sentry` copies `c.Body()` on every request before anything panics; `coraza` and `hcaptcha` read the whole body; the websocket read limit counts frame bytes, so check whether it bounds the decompressed size when `EnableCompression` is on; `opa` policy cost with attacker-chosen input.
7. **Request-owned memory kept past the request.** `02877c2d` (`sentry`), `c8da20e3` and `7ab4b0ba` (`websocket` captures the request before the upgrade and allocates a `Conn` per upgrade instead of pooling), `689994b6` (`spnego`), `727faaed` (`prometheus`), `1fd03ba2` and `5b195386` (`socketio`). Siblings: every `utils.UnsafeString` or `UnsafeBytes` result (only `opa` and `otel` use them), every closure over `c` that runs after the handler, `Locals` and `Params` captured for a goroutine.
8. **The module reads a value differently from the router or the proxy.** `4c06e2c9` and `42df32b5` (`jwt`: a form parameter reads the query first, so the URL can carry a credential), `dc95f4b9`, `baa3081d` and `4edb5034` (`uptime` favicon authorities, aligned with Fiber), `59ffd38e` (`spnego` follows a change in how Fiber reports the scheme). Siblings: guards that compare `c.Path()` as an exact string (`monitor` and `prometheus` through `Next`, `fgprof`, `swaggerui`, `uptime`'s `matchUptimeRoute`) against Fiber's case-insensitive, non-strict router and its normalization; `casbin` and `opa` policies on `c.Path()`; and repeated header lines (which one `c.Get` returns, against which one the proxy or an upstream uses). Also every place a module reads a forwarding header itself instead of through Fiber's accessors, which honor `TrustProxyConfig` (`grep -rnE 'X-Forwarded|HeaderXForwarded|X-Real-IP|HeaderXRealIP|HeaderForwarded' --include='*.go' v3 | grep -v _test.go` finds three), and where that value ends up: a `Location`, a script URL, a log line.
9. **A credential or a response ends up in a shared cache.** `82b7e7fb`, `9af34acf`, `8fb7f376` and `2d99934b` (`jwt`: a response to a request whose URL carries a token is marked private; the cache must sit inside the middleware). Siblings: `Cache-Control` on every page the modules serve (they differ: `no-store` in `monitor` and `uptime`, `public, max-age` on the `swaggerui` spec, none in `swaggo`), `Vary` on `i18n` output, and a handler that replaces the header the middleware set.
10. **A generation, lifecycle or ownership mix-up under concurrency.** `circuitbreaker`: `f6fb641a`, `2d6e5071`, `38b1fc19`, `4a89e7a6`, `9a9aae61`. `socketio`: `0bc8e33c`, `801c4a4a`, `cc607c11`. `websocket`: `f4e73fb4`, `1a2304bf`. `coraza`: `ee171524` (drain scope on `Reload`). Siblings: `Close`, `Shutdown`, `Drain`, `Reload` and `Stop` against in-flight work in every stateful module; the deprecated `circuitbreaker` calls (`AllowRequest`, `ReportSuccess`, `ReleaseSemaphore`) mixed with `Middleware`; timers that fire after teardown.
11. **Strictness that a library does not provide.** `3cadcad0`, `6d1093b9`, `c8c5cd58` (`jwt`: `crit`, `b64`, reserved JOSE names), `f9add282` (`spnego`: a configuration option promised a restriction and did nothing). Siblings: any option whose effect the code never reads, and any check the README claims that a library may skip (`paseto` footers, `casbin` model matchers, Coraza's body limit against Fiber's).
12. **A dependency or Fiber changed under the module.** `b86af947` (`jwt` gained `ParserOptions`), `444e797d` (#1935, `swaggerui` YAML parser), `d61782e6` (Fiber's timeout status), `59ffd38e`. Siblings: a Fiber behavior a module re-implements (favicon validation, scheme and host, `Next` semantics, `ErrorHandler` timing in `monitor`) that has since moved.

## Hypotheses worth testing

Each is a test with an oracle. Skip one if the existing tests already cover it at the depth you would reach.

1. **The `socketio` gate matrix.** For each of: WebSocket text and binary frames, `0x1E`-batched frames, polling POST (plain, base64 `b`-packets, batched, `Content-Encoding`), concurrent POSTs, a POST racing the GET drain, a second CONNECT for another namespace, a CONNECT the application refused in its `New` callback or by a bad auth blob, and a packet after `Close`, the oracle is the same: no listener runs for anything but an accepted CONNECT, and nothing runs after the session is marked disconnected. The existing helpers (`newPollingTestServer`, `pollOpen`, `pollGet`, `pollPost`, `newSIOTestServer`, `dialSIO`) make each case a few lines.
2. **Key scoping.** For each piece of state stored under a key a client can present or influence (the `socketio` and `websocket/event` pools and their UUIDs, Engine.IO session ids, `spnego` sessions, `uptime` service ids and key prefixes, `prometheus` series, `jwt` `kid` lookups), ask who else can present the key, what it is bound to, and whether any API lets the application replace it. Oracle: two clients and one key, compare what each can read or cause.
3. **Path differentials.** Put a policy or a `Next` predicate on `/admin` (`casbin`, `opa`, and the pages gated through `Next`), mount an always-401 guard on the prefix, and request every spelling of the path (case, trailing and doubled slashes, percent-encoding, dot segments, `;` parameters, `OPTIONS *`, absolute-form targets) with `UnescapePath`, `CaseSensitive` and `StrictRouting` on and off. Oracle: no spelling reaches the protected handler or page without the policy or guard running, and none is served by a module the application gated on another spelling.
4. **`jwt` against a reference.** Over `SigningKey`, `SigningKeys`, `JWKSetURLs` and `KeyFunc` configurations, and extractor chains, compare the middleware's verdict with `golang-jwt` run directly with the same options. Add key-type confusion (an RSA public key as an HMAC secret), missing and duplicate `kid`, JWKS entries whose `alg`, `use` or `key_ops` disagree with the token, and a JWKS server that answers slowly, with a huge body, or with a different key after a `kid` miss (`RefreshUnknownKID` makes a token with an unknown `kid` trigger a fetch). Oracle: stricter is fine, looser is a finding, and an unauthenticated client cannot cause unbounded outbound work.
5. **`spnego` under hostile input.** Feed `Authorization: Negotiate` values that are empty, truncated, oversize, nested and ASN.1-malformed, with and without `DisablePACDecoding`, and a `SessionManager` and hooks that panic or block; rotate the keytab on disk under concurrent requests. Oracle: never a 2xx without a valid ticket, no panic outside the recovered frames, bounded work per request, no key material in any response or log line.
6. **Fail-open audit.** The inject-and-observe check under promise 2, applied to every module that gates a request, including `monitor`, `uptime`, `fgprof`, `swaggerui` and `coraza` `Next`/`BlockHandler`/`ErrorHandler`.
7. **Output audit.** Send hostile values (CR, LF, NUL, invalid UTF-8, 10 KB tokens, `</script>`, JSON metacharacters, `;` and `,` in header values) through every request-derived value a module writes into a header, a response body, an HTML or JS template (`monitor`, `uptime`, `swaggo`, `swaggerui`), a log line (`zap`, `zerolog`, `spnego`, `coraza`, `websocket`), a metric label or a span attribute. Oracle: no extra header, line, series or attribute, and no raw secret.
8. **Resource audit.** For each module and each request-derived size, count or label, measure memory and time at n, 2n and 4n inside `BodyLimit`; flag a ratio above 3 per doubling. Include `EnableCompression` on `websocket`, `Content-Encoding` on polling POSTs, `opa` with a costly policy, `uptime` routes under load, and the `fgprof` `seconds` parameter.
9. **The `websocket` handshake and teardown on a real listener.** Use a socket against `app.Listen("127.0.0.1:...")`: partial, duplicated and oversize handshake headers, a `Sec-WebSocket-Extensions` already set by earlier middleware, `Origin` spellings against `Origins` (case, default ports, trailing dot, `null`, userinfo), bytes pipelined right behind the handshake (the `stash` in `coalescingConn.attach`), a client that stops reading, close during the handshake, TLS terminated by Fiber against plain TCP. Oracle: nothing lost, duplicated or reordered; the connection ends within bounded time; no goroutine is left behind (the `websocket/event` tests already run `goleak`).
10. **The `uptime` Redis store against a real Redis**, with the model-based oracle of an injected clock: retention and TTL math, rollups, instance metadata expiry, `RemoveService`, key prefixes that differ only in colons (the prefix is normalized by trimming them), and two instances sharing a prefix with different intervals. Oracle: no key outside the prefix, no growth beyond the documented bounds, no status that contradicts the heartbeats written.
11. **State machines with a fake clock**: `circuitbreaker` through every state with concurrent admissions, `Interval`, `ForceOpen`, `SetTimeout` and the deprecated calls; `loadshed` thresholds; `jwt` JWKS refresh timing; `socketio` heartbeat, handshake and close timers. Oracle: compare with a small model.
12. **Coverage as a map of untested code**: `go test -coverprofile=/tmp/c.out ./... && go tool cover -func=/tmp/c.out | sort -k3 -n | head -40` in each module, then read the uncovered branches of the files under "Components that matter most". Coverage is already high in `spnego` (the maintainers enforce an 85% floor in CI), so the value is in the modules that were not part of the cycle.

## How to exercise it

The image has the checkout at `/src` with its full git history, Go 1.27.3, every module's dependencies in the module cache, every package and test binary already compiled (plain and with `-race`), `redis-server` installed but not running, `GOPROXY=off` and `GOTOOLCHAIN=local`. `/src/.oss-scanner/` is the scanner's own untracked copy of the Dockerfile; keep it out of patches. `curl`, `nc`, `python3`, `gdb`, `strace` and `valgrind` are installed, only loopback is reachable, and the shell has two CPUs and 8 GB. `golangci-lint` is not installed; use `go vet ./...` and `gofmt -l .`.

- **One module at a time.** There is no `go.work`, so run every `go` command inside the module: `cd /src/v3/<name>`. Its tests: `go test -race -count=1 ./...`. On four CPUs the slowest are `socketio` (about 36 s) and `loadshed` (about 13 s) and the others take a few seconds, so iterate with `-run`.
- **History.** `git log --no-merges --since=2026-07-01 --format='%h %ad %s' --date=short -- v3/socketio | head -40` lists recent fixes to a module; `git log -S'<text>' -- <file>` finds when a line appeared; merge commits carry the PR number.
- **A server to attack.** Put a throwaway `main` package in a new directory inside the module under test, such as `/src/v3/jwt/poc/main.go`, written from the module README, and run it with `go run ./poc` on `127.0.0.1`. Delete it before you write a patch. Raw bytes with `nc` are the faithful way to test anything that depends on the exact request line or handshake.
- **Unexported helpers.** A scratch `zz_probe_test.go` placed in the package directory, in the same package as that module's tests (`package socketio`, `package websocket`), can use their helpers: `socketio` has `newPollingTestServer`, `pollOpen`, `pollGet`, `pollPost` (polling) and `newSIOTestServer`, `dialSIO` (WebSocket); `websocket` has `setupTestApp` and `handshakeRequest`. Run it with `go test -run TestZZ -v -count=1 .` and delete it afterwards.
- **Two modules together.** `socketio` builds against the published `websocket` `v1.2.9` from the module cache, not against `/src/v3/websocket`. To test the local pair, run `cd /src && go work init ./v3/websocket ./v3/socketio` (it works offline) or `go mod edit -replace github.com/gofiber/contrib/v3/websocket=../websocket` in the module, and remove `go.work`, `go.work.sum` or the `replace` before you write a patch.
- **Fuzzing** works offline. `socketio` has eleven targets in `socketio_fuzz_test.go`: `cd /src/v3/socketio && go test -run '^$' -fuzz FuzzParseSIOEvent -fuzztime 2m .`. No other module has one.
- **Races and leaks.** `go test -race -count=20 -run <test> .`; the tests of `websocket/event` run `goleak`.
- **Redis for `uptime`.** Start it with `redis-server --daemonize yes --bind 127.0.0.1 --save '' --appendonly no`. The module's own integration test starts Redis through Docker and cannot run here; its helpers take a URL, so a scratch `zz_redis_test.go` in `package uptime_test` that calls `testRedisStoreQueriesAndWrites(t, url)`, `testRedisStorePrefixes(t, url)` and `testRedisStoreRuntimeAndTTL(t, url)` with `redis://127.0.0.1:6379/0` runs the same checks against the local server.
- **Dashboards.** `monitor` renders `dashboard.gohtml` once when the middleware is built, `uptime` on every request; to see a page, run a `main` that mounts the module and fetch it with `curl`.

### A starting point for `socketio` polling

Save as `/src/v3/socketio/zz_skeleton_test.go` and run `cd /src/v3/socketio && go test -run TestZZSkeleton -v -count=1 .`. It opens a polling session, completes the Socket.IO CONNECT and drains what the server queued (it logs `40{"sid":"..."}` and `42["hello","world"]` joined by `0x1E`). Extend it with the cases of the gate matrix, and delete it before you write a patch.

```go
package socketio

import (
	"testing"
	"time"

	"github.com/stretchr/testify/require"
)

func TestZZSkeleton(t *testing.T) {
	connected := make(chan struct{}, 1)
	_, client, closeFn := newPollingTestServer(t, func(kws *Websocket) {
		kws.EmitEvent("hello", []byte(`"world"`))
		connected <- struct{}{}
	})
	defer closeFn()

	sid, _, status := pollOpen(t, client) // GET /?EIO=4&transport=polling opens a session
	require.Equal(t, 200, status)
	_, status = pollPost(t, client, sid, []byte("40")) // the Socket.IO CONNECT packet; the New callback runs now
	require.Equal(t, 200, status)
	select {
	case <-connected:
	case <-time.After(3 * time.Second):
		t.Fatal("callback did not run")
	}
	body, status := pollGet(t, client, sid) // long-poll drain of what the server queued
	t.Logf("%d %q", status, body)
}
```

## How you rate severity

A finding counts when a network client of an application that uses these modules as their README describes can make it misbehave. State the `Config`, the Fiber configuration and the Go code of the application that the reproducer needs. A finding against the defaults, or against the configuration the README recommends, weighs more than one that needs an unusual option. The maintainers fixed `socketio` polling gates, a fail-open `Next` and unbounded metric labels as vulnerabilities, so rate those classes seriously even when the trigger looks small.

- **Critical**: an authentication or authorization bypass in a verifier or policy module under its documented configuration: `jwt`, `paseto` or `spnego` accepting a forged, unsigned, wrong-key or wrong-algorithm credential, or an expired one where expiry is enforced; `casbin` or `opa` allowing what the policy denies through any spelling of the path or method. Application code reached by a `socketio` or `websocket` client that the handshake or the application's auth refused or never saw. Data from one client delivered to another (an event, a session, a response, a `Conn`). A session reachable with an identifier its client was not issued. Memory corruption or a data race on a string, slice or interface.
- **High**: a panic or fatal error that one unauthenticated request triggers in a module under its default or documented configuration, because the process exits (nil dereference, index out of range, concurrent map access, unbounded recursion, out-of-memory). A security decision that fails open on an error or a panic. Memory, CPU, goroutines or series growing from small unauthenticated requests beyond the documented bounds: per request, per connection, per label or per key. Keytab bytes, tickets, tokens, cookies, DSNs or panic values reaching a client, a log or a telemetry sink by default. Script injection into a page a module serves, header or response splitting, or an unauthenticated header that reaches `Location` or a script URL. A WAF bypass through a parsing difference between `coraza` and the router for a request the active rules block.
- **Medium**: the High denial-of-service, leak and fail-open classes when they need a non-default option (polling, `EnableCompression`, a particular `Config`). A cache or `Vary` mistake that lets a shared cache mix users. A forwarding header trusted without `TrustProxyConfig`. An availability control that one client can trip or disable in a way the README does not describe. Information exposure beyond what a page's README says. Log injection with a default format.
- **Low**: hardening gaps (a redaction list shorter than a sibling's, a missing `nosniff`), a documented but surprising default, a crash that only the application's own handler or configuration can cause.

When a finding sits between two levels, choose the lower and say what would raise it. A deviation from an RFC with no security consequence is a bug and not a vulnerability; do not report it.

## How to report

Verify before you report. A finding needs all of these:

1. A reproducer that runs in this image from a clean checkout: a Go test in the module concerned, or a small `main` plus the exact bytes or `curl` command sent, the Fiber and module configuration, and what you observed against what the README promises. For resource exhaustion, give the measured memory or time against the configured limit at two sizes.
2. A check that it is not intended: read the module README and search the tests (`grep -rn '<behavior>' --include='*_test.go' v3/<name>`; `git log -S'<text>'`). A test that pins the behavior, or a README that describes it, usually means it is deliberate.
3. A check that it is present on `main` now (`git log --oneline -5 -- <file>`) and in which module version (`git tag --contains <commit>`).
4. A minimal patch against `main` with a regression test written as the module writes its tests (most use `testify/require`; `t.Parallel()` is common, but `socketio` does not use it because its tests share package-level settings). The test must fail before the patch and pass after it, with `go test -race` on the package. Change only the module concerned; there are no cross-module `replace` directives to update, and a fix that needs a newer Fiber or dependency version is a `go.mod` bump in that module. Update the module README when a documented contract changes.

Report one root cause once, listing each module it reaches. Say plainly when a finding depends on something this image cannot reproduce (Docker, a TLS-terminating proxy, Windows or macOS), and what you checked instead. Do not report best-practice gaps without a concrete request that misbehaves.

## Anything to leave alone

- Pages and endpoints that serve data by design when mounted without authentication: `monitor`, `uptime` (dashboard and JSON), `prometheus` metrics, `fgprof` (profiles, and the `seconds` parameter), `swaggerui`, `swaggo`, `circuitbreaker`'s `HealthHandler` and `Metrics`, and `coraza`'s `Snapshot()` and `Report()` (the README says they include server paths and must stay internal). The `monitor` README tells operators to protect its endpoint. Report only an exposure beyond what the README and `Config` say.
- `websocket`: an empty `Origins` allows every origin, `AllowEmptyOrigin` governs a missing `Origin`, and `websocket.New` sets no read limit (the README says to call `SetReadLimit`). The `event` and `socketio` limits are documented defaults, and `socketio`'s README lists its known limitations (one namespace per connection, no binary events, no connection-state recovery, no polling-to-WebSocket upgrade) and its production notes (rate limiting, `WriteTimeout`, burst sizing, CORS are the application's job).
- `loadshed` fails open on a sampler error or panic, by design. `circuitbreaker` counts any response of 500 or more as a failure by default, so a client that can cause one can open the circuit for everyone; that is how the pattern works.
- `jwt`: `aud`, `iss`, `typ` and `jti` are checked only when the application asks for them (`ParserOptions`); `jwt.WithoutClaimsValidation` turns `exp` off; a `SigningKey` without `JWTAlg`, a `KeyFunc` and `JWKSetURLs` leave the algorithm to the key material; a `KeyFunc` may read anything in the header; `jwt.UnsafeAllowNoneSignatureType` accepts `none`; a missing token is a 400; a token in the query string, a form field or a route parameter is exposed through URLs (the README warns, and the middleware marks such responses private); a cache registered in front of the middleware serves hits unauthenticated, and the README says to register it behind.
- `spnego`: `KeytabLookup` runs on every request; with no `KeytabPrincipal` any principal in the keytab is accepted; the `SessionManager` and everything it stores are the application's responsibility; `service.SName` has no effect and the README says so; `chmod` alone does not revoke a keytab the cache already holds.
- `paseto` and `hcaptcha`: a custom `Validate` or `ValidateFunc` replaces the default checks; the README of `hcaptcha` says to reject when `success` is false. `coraza` blocks nothing until rules are loaded, does not inspect responses, follows Fiber's `BodyLimit`, and the built-in block handler sets `X-WAF-Blocked`; behind a proxy, `REMOTE_ADDR` is only as good as `TrustProxyConfig`.
- Constructors that panic at startup on a contradictory configuration (`jwt` without a key, `prometheus` with an invalid label or bucket, `coraza` with an unreadable directives file, `paseto` with a wrong key size) refuse a bad configuration on purpose. `MustLocalize` and `MustGetHubFromContext` panic by contract.
- `sentry`, `newrelic`, `otel`, `zap` and `zerolog` send what the application configures to the sink it chose; `otel` records `enduser.id` from a Basic `Authorization` header and propagates baggage as documented. A value you can put in a log or a trace is not a finding unless a documented redaction or bound fails to apply.
- Linear amplification inside Fiber's `BodyLimit` and `ReadBufferSize`, or inside a module's documented limit (a polling POST at `PollingMaxBufferSize`, a frame at `MaxMessageSize`). Report super-linear growth, or amplification that escapes the limit.
- The tests that need a Docker daemon (`testcontainers`, and `uptime`'s `TestNewRedisStoreIntegration`): they fail in this image for want of Docker.
- Findings that exist only in Fiber core, fasthttp or another third-party module (see "Dependencies"), in the `v2` branch, or only in `_test.go` files, `example/` programs, `testdata/`, READMEs, dashboards and `.github/`.
