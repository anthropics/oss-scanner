# DeepSeek MCP Server

## Purpose and code

This MIT-licensed TypeScript/Node.js package connects MCP clients to DeepSeek
APIs. It is distributed on npm as `deepseek-mcp-server`. It supports local
stdio clients and a Streamable HTTP endpoint. Tools expose chat, Responses,
FIM completion, file upload/list/retrieve/delete, model and balance queries,
and process-local conversation storage.

Review source in `src/`; `build/` is generated by TypeScript. Main areas:

- `src/index.ts` and `src/config.ts`: startup, environment configuration,
  transport selection, and shutdown.
- `src/transports/http.ts`: request routing, Origin checks, CORS, and MCP
  HTTP handling through the SDK.
- `src/mcp-server.ts`: tool/resource/prompt registration and output shaping.
- `src/deepseek/schemas.ts` and `src/deepseek/image-data.ts`: untrusted tool
  arguments, image/base64 validation, and upload size limits.
- `src/deepseek/client.ts`: provider requests, URL construction, file handling,
  streaming response parsing, error handling, and timeouts.
- `src/conversation-store.ts`: conversation retention and access.

## Trust boundaries and priorities

The operator controls environment variables, including the DeepSeek API key,
base URL, bind address, timeout, and browser Origin allowlist. Treat requests,
tool arguments, HTTP headers, conversation IDs, filenames, base64 content, and
provider responses as potentially adversarial. A configured base URL is an
operator choice; determine whether an untrusted argument can alter the request
destination, path, or credential recipient beyond that choice.

The default HTTP bind address is `127.0.0.1`. Requests with an Origin header
must match the configured exact allowlist; native clients can omit Origin.
This package does not implement bearer authentication or per-user tenant
isolation. Public remote deployments need a separate access-control layer.
The separately hosted endpoint's authentication and infrastructure are not
contained in this repository. Explain the required deployment conditions for
findings rather than assuming every reachable client is a different tenant.

Conversation state is shared within a server process. The configured message
limit applies per conversation; it does not cap the number of conversations.
Examine resource exhaustion and cross-request behavior with realistic attack
preconditions, including local-browser access to a loopback HTTP service.

Prioritize credential or unintended data disclosure, arbitrary code execution,
unintended local file access or server-side network requests, Origin/HTTP
boundary bypass, request/path manipulation, and practical denial of service.
For uploads, review the 64 MiB decoded limit, canonical base64 checks, image
signature checks, filenames, and file IDs. The documented interface accepts
encoded image bytes, not arbitrary local filesystem paths. Distinguish URLs
forwarded to DeepSeek from URLs actually fetched by this server.

MCP clients intentionally receive requested completions, file metadata, and
account information under the operator's provider account. Raw provider
responses are opt-in. Model output is data; the server does not execute model
tool calls as local commands. Report prompt injection only when it demonstrates
a concrete security boundary failure in this repository.

## Offline build and tests

The enrollment Dockerfile keeps the full checkout at `/src`, installs locked
production and development dependencies, and runs `npm test` during the build.
Inside the image, use:

```sh
cd /src
npm test
```

This compiles the source and runs `test/*.test.ts` with Vitest. Tests use mock
provider responses and local transport connections; they require no real API
key or Internet access. `npm run build` recompiles source after a change.
For additional reproducers, use a dummy API key and mocked fetch or a local
HTTP fixture. Do not run `test:live` or `test:remote`: these require external
services and real credentials. Do not probe hosted services or user accounts.

## Reports

Provide an affected commit, relevant source locations, attacker capabilities,
deployment preconditions, observed impact, and a minimal offline reproducer.
Prefer a regression test and a focused TypeScript patch; do not hand-edit
generated `build/` files. State whether a flaw is in this package or a reachable
dependency, and deduplicate findings with the same root cause.

Base severity on demonstrated impact and reachability. Separate unauthenticated
remote or local-browser attacks from attacks requiring an already trusted MCP
client or operator control. Out of scope are defects solely in DeepSeek's
service, external hosting infrastructure, and speculative dependency alerts
without an affected reachable code path in this package.
