# How we would like reports written

## Layout and length
- e.g. "under one page, with these sections in this order: Summary, Affected versions, Reproduction, Suggested fix"

## What every report should state
- e.g. "the affected versions and configuration, the attacker's starting position, and the public API that reaches the faulty code"

## Style
- e.g. "plain text, no Markdown tables; one root cause per report; start the title with the component's name"
